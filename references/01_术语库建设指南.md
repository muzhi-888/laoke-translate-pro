# 术语库建设指南

> 术语库是翻译质量的地基。先定标准，再动手翻。

## 一、为什么必须有术语库
- 同一概念全程同一译法，否则读者困惑、专业度归零。
- 复用：翻过的词不用再查，效率翻倍。
- 可审计：译法有依据，争议可回溯。

## 二、字段规范（glossary.csv）
```
src,tgt,domain
cache,缓存,计算机
throughput,吞吐量,计算机
bank,银行,金融
bank,库,数据
```
- src：源词（小写规范形）。
- tgt：目标译词。
- domain：领域，用于同形异义区分。

## 三、录入原则
1. 一词一主译，多义标领域。
2. 专有名词优先业内通用（K8s、Redis 不译）。
3. 品牌/产品查官方中文名，不自创。
4. 新术语即时录，别攒堆。
5. 锁定"不译"项（代码、命令、品牌），防机翻改坏。

## 四、组织方式
- 分领域独立库：glossary_tech.csv / glossary_finance.csv。
- 随项目版本管理，改动留记录。
- 项目结束抽 20 条评审，错的立刻修。

## 五、常见错误
| 错误 | 后果 | 修正 |
| --- | --- | --- |
| 一词多译无领域 | 串义 | 标 domain |
| 自创品牌译名 | 不专业 | 查官方名 |
| 漏录高频词 | 前后不一致 | 翻到即录 |
| 全局混用一库 | 串领域 | 分库隔离 |
